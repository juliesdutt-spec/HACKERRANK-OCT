# Start here: beginner guide (VS Code + GitHub Copilot)

You do not need Claude Code or Codex. A free editor with an AI chat is enough. This guide covers where to code, how to set up, and how to work with Copilot step by step. The task itself is written in `02_PRD_for_Copilot.md`.

## 1. Where to code

Use the official starter repo, not a copy of someone else's work:

```
git clone https://github.com/interviewstreet/hackerrank-orchestrate-october26.git
```

| File or folder | What it is for |
| --- | --- |
| `code/main.py` | The entry point (empty at the start). Keep it short: load data, loop over all 518 requests, write `output.csv`. |
| `code/*.py` (new files you add) | The real logic, one idea per file, for example `identity.py`, `evidence.py`, `decide.py`, `steps.py`. |
| `code/evaluation/main.py` | Your scorer. It compares your output to `dataset/sample_output.csv`. |
| `code/evaluation/` | Put `evaluation_report.md` and `usage_report.md` here. |
| `output.csv` (repo root) | Generated by your program. This is what you submit. |
| `dataset/` | Read only. Never edit these files. |

Run it with `python3 code/main.py` (on Windows: `py code\main.py`).

## 2. One-time setup (about 20 minutes)

1. Install **VS Code**, **Python 3.10 or newer** (python.org; on Windows tick "Add Python to PATH"), and **Git**.
2. In VS Code, sign in to GitHub and turn on **Copilot Free**. Open the Chat panel.
3. Clone the repo, then use **File > Open Folder** and choose the **repo root** (the folder that contains `AGENTS.md`). Opening the root matters: it is how the session gets logged.
4. In the VS Code terminal run `python3 --version` (Windows: `py --version`) to check Python works.
5. Copy `02_PRD_for_Copilot.md` into the repo root and rename it `PRD.md`.
6. First message to Copilot Chat: **"Read AGENTS.md and PRD.md in this repo. Follow AGENTS.md for this whole session, including logging to log.txt."** After its reply, check that `log.txt` appeared in the repo root. If it did not, ask again: "Please create log.txt and append the entry exactly as AGENTS.md describes."

`log.txt` is your required `chat_transcript`. Do not edit it by hand.

## 3. The working loop (repeat for each milestone in the PRD)

1. Ask: **"Do only Milestone N from PRD.md. Keep it simple and add a small test."**
2. Ask: **"Explain what you wrote in plain words, file by file."** You will need to explain your own design in the live AI interview, so do not skip this.
3. Run the test or the program. Compare with the milestone's acceptance check.
4. If something is wrong, paste the error or the wrong output back into chat.
5. Save your progress with Git: `git add -A`, then `git commit -m "milestone N"`.

Copilot Free has a monthly chat limit (check the current numbers in your account). Make fewer, bigger, clearer requests, and read the PRD sections before asking.

## 4. Rules that can cost you the submission

- Use only the files under `dataset/`. Never use hidden answers or organizer files.
- Do not hardcode per-case answers. The logic must work from the data.
- No API keys or passwords in code, `log.txt`, or the zip. Use environment variables and an uncommitted `.env` file.
- The program must be deterministic: same input, same `output.csv`.

## 5. Submission checklist

- [ ] `output.csv` at the repo root: header `case_id,deletion_status,steps_json`, exactly 518 rows, sorted by `case_id`.
- [ ] Every `steps_json` is valid JSON with steps numbered 1, 2, 3...
- [ ] `code.zip` containing `README.md` and the `code` folder (no `dataset/`, no `.venv`, no `__pycache__`, no nested zips). The zip commands are in the repo README.
- [ ] `code/evaluation/evaluation_report.md` and `code/evaluation/usage_report.md`, with the numbers written inside the Markdown.
- [ ] `README.md` with clear setup and run steps.
- [ ] `log.txt` uploaded as the chat transcript.
- [ ] Agent trace zip if requested: see `agent_trace_instructions.md` ("Other Harnesses" section). For Copilot, export the chat from VS Code and include it.
- [ ] Be ready to explain the architecture, how you investigate each case, how you plan remediation, and how you evaluated.

## 6. If you get stuck

Do the milestones in order. A simple version that gets the status right for most cases is worth more than a complicated one that is unfinished. After Milestone 5 you already have a working `output.csv`.
